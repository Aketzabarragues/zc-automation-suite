El objetivo cumplido

Antes, el shell SPA mezclaba chrome común con chrome específico del área (la AlimentacionSidebar envolvía todo). Cualquier cambio de UI requería tocar la carpeta del área, y añadir un segundo departamento implicaba duplicar el sidebar. Después, el shell lee del store y el área solo aporta sus vistas concretas.

Cómo añadir un área nueva

Lo que era el objetivo del refactor. Secuencia exacta:

1
Crear la carpeta del área
Estructura autocontenida con sus capas DDD (application / domain / data / infrastructure / frontend / functions).
areas/<area_id>/
no toca core
2
Definir el AREA_SPEC
Dataclass frozen en core/composition/app_area_registry.py. Aquí se declaran los hooks: contributes_frontend_manifest, contributes_routers, contributes_mcp_tools, etc.
areas/<area>/__init__.py
no toca core
3
Crear el manifest (espejo Python y JS)
Mismo shape en ambos archivos. Lista de vistas del área (views) y sus labels (viewLabels). Si falta viewLabels, el sidebar usa la key capitalizada.
frontend/manifest.py + frontend/manifest.js
no toca core
4
Implementar los componentes específicos
Una vista por cada key del manifest. Vue 3 ESM, sin build step. Estado en store.js, fetch en api.js.
frontend/components/
no toca core
5
Registrar el área en config
Bloque declarativo bajo departments.<id>. El engine lo descubre al arrancar.
config/config.json
no toca core
6
Arrancar y validar
El shell lee /api/v1/areas, Welcome muestra la card del nuevo área, al pulsarla carga su manifest vía area-loader.js y monta sus vistas en ShellSidebar automáticamente.
Welcome → area-loader → ShellSidebar
cero código nuevo en shell

Decisiones clave

"plc" como key reservada del shell

onShellNavigate cortocircuita "plc" sin pasar por goToSubview. El sidebar nunca manda "plc" al validador del área.

goToSubview se mantiene puro

Solo valida keys del área contra el manifest. El shell se entiende con el área sin contaminar su contrato.

Label derivado del key

capitalize("alimentacion") → "Alimentacion", no el label completo del backend ("Área de alimentación"). El sufijo "Área de / Departamento de" es ruido con el caption "Área" arriba.

threaded=True en Flask

SSE de larga vida no bloquea otras requests. El store no es thread-safe pero la SPA solo lee; las escrituras vienen del main loop.

El área no aporta nada común al shell

Solo manifest.{py,js} + componentes específicos. El botón PLC, el breadcrumb y el footer son siempre del shell.

Tolerancia a loaders rotos

area-loader.js usa .catch por import dinámico. Un componente que falla no tira el área entera.
